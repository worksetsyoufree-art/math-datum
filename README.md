# math-datum

Локализация ГНСС (пары точек WGS-84 ↔ местная система → датум → пересчёты), пересчёты между
государственными системами координат по ГОСТ 32453-2017, а также наборы точек и эталонные результаты
для их проверки.

## Локализация

```
pip install -r requirements.txt

python -m mathdatum localize examples/pairs.csv -o datum.json      # расчёт датума + отчёт по невязкам
python -m mathdatum to-local datum.json examples/wgs_points.csv -o local.csv   # B L h → x y H
python -m mathdatum to-wgs   datum.json local.csv -o wgs.csv                   # x y H → B L h
python -m mathdatum proj datum.json                                 # строка PROJ для QGIS / cs2cs

python -m mathdatum localize examples/pairs.csv --suggest           # + какие точки исключить (по худшему |w|)
python -m mathdatum to-local datum.json examples/wgs_points.csv -o local.csv --quality   # + outside_m;m_plan;m_H
```

`localize` печатает параметры, избыточность, СКО единицы веса, таблицу невязок с нормированными
поправками |w| и ошибками «без точки» (leave-one-out) и предупреждения. Параметры: `--sigma-plan 0.02`,
`--sigma-height 0.03` (априорные СКО, м), `--w-limit 3.29`, `--max-scale-ppm 200`, `--max-rotation-deg 3`.
`to-local` / `to-wgs` перечисляют в stderr точки вне выпуклой оболочки опорных пунктов (экстраполяция);
формат файла без `--quality` прежний (`name;x;y;H` / `name;B;L;h`), с `--quality` добавляются столбцы
`outside_m` (расстояние до оболочки, 0 — внутри), `m_plan`, `m_H` (ожидаемая СКО прогноза, м).

Формат пар (`examples/pairs.csv`): `name;B;L;h;x;y;H;use`. B, L — градусы WGS-84 (или системы
`--gnss-datum`), h — высота ГНСС (эллипсоидальная), x — север, y — восток, H — местная высота. `use`: `both` (по умолчанию), `plan`,
`height` или `none` — точка не участвует в расчёте, но для неё печатается ошибка (контроль).
Необязательные столбцы `sigma_plan;sigma_height` — априорная СКО точки, м (план — на одну координату):
суммарная точность каталога и ГНСС, `√(σ_кат² + σ_ГНСС²)`. Пусто или столбца нет — глобальная σ0
(`--sigma-plan` / `--sigma-height`); старые файлы читаются без изменений. При весах в отчёте есть столбцы σ.

Из Python:

```python
from mathdatum import Pair, localize, LocalizationDatum
d = localize([Pair("R1", 55.05, 39.27, 215.5, -200498.03, 3258049.82, 209.38), ...])
x, y, H = d.to_local(B, L, h)
B, L, h = d.to_wgs(x, y, H)
d.save("datum.json"); d = LocalizationDatum.load("datum.json")
```

Модель (`mathdatum/localization.py`):
1. Рабочая проекция — поперечный Меркатор на эллипсоиде системы ГНСС-измерений (по умолчанию WGS-84)
   с центром в среднем по точкам.
2. План — подобие (сдвиг, разворот, масштаб) относительно взвешенного центроида точек.
3. Высота — наклонная плоскость `H = h + c0 + c1·dN + c2·dE`.

Обе подгонки — взвешенный линейный МНК в замкнутой форме. Вес точки `p = σ0² / σi²` (σ0 — глобальная
σ, σi — своя σ точки; без неё `p = 1`). План: `zc = Σp·z / Σp`, `k = a + ib = Σp·conj(z − zc)·(w − wc) / Σp·|z − zc|²`
(`z = N + iE`, `w = x + iy`); высота — плоскость по данным, центрированным на взвешенное среднее.
При равных весах результат совпадает с невзвешенным (до округления, < 1e-12 относительно). Если точек мало, модель упрощается: 1 точка в плане
даёт только сдвиг; 1–2 точки по высоте или точки на одной линии дают только сдвиг по высоте.

### Надёжность

Только диагностика: точки автоматически не исключаются (`suggest_exclusions` лишь предлагает
исключать худшую точку итеративно).

- **Избыточность:** `r_plan = 2n − 4` (сдвиг `2n − 2`), `r_height = n − 3` (сдвиг `n − 1`). При `r = 0`
  невязки нулевые, контроля нет — предупреждение.
- **Нормированные поправки (тест Баарда):** `w = v / (σ0·√q_vv)`, `q_vv = 1/p − aᵀQa`, `Q = (AᵀPA)⁻¹`,
  σ0 — априорная СКО единицы веса на одну координату (0.02 м в плане, 0.03 м по высоте); при `p = 1`
  это `v / (σ·√(1 − aᵀQa))`. `Σ p·q_vv = r`. `|w| > 3.29` — точка подозрительна. В плане `q_vv` по x и y
  одинаков: `1/p − 1/P − ρ²/S`, `ρ` — расстояние до взвешенного центроида, `P = Σp`, `S = Σp·ρ²`. Подсветка «невязка > 3·СКО» не годится: `max|v| ≤ √n·СКО`, при `n ≤ 9` она не срабатывает,
  а выброс ещё и раздувает СКО. Для 6 пунктов и σ = 2 см минимальная надёжно обнаруживаемая ошибка ≈ 10 см;
  соседние близкие пункты тоже получают большие |w| («размазывание»), виноват — худший.
- **Ошибка без точки (leave-one-out):** датум пересчитывается без точки (в той же рабочей проекции)
  и даёт ошибку прогноза в ней; равна `v / (p·q_vv)`. Если без точки модель вырождается или меняется
  (например, плоскость → сдвиг) — `None`, «нельзя проверить». Для контрольных точек (`use = none`) —
  сама невязка, `q_vv = 1/p + aᵀQa`.
- **Ковариации и точность прогноза:** `covariance_plan()`, `covariance_height()` = `σ²·Q` (априорная σ0
  или `posterior=True` — апостериорная `s0 = √(vᵀPv/r)`); `prediction_sigma(B, L)` = `σ·√(aᵀQa)`
  (план — радиальная по x и y).
- **Веса:** точка с большой σ почти не влияет на датум (и её ошибка не помечается, если укладывается в
  её σ), точка с малой σ «притягивает» решение. Использованные σ и веса — в `Residual.sigma_plan`,
  `sigma_height`, `p_plan`, `p_height`.
- **Экстраполяция:** `outside_distance(B, L)`, `quality_wgs`, `quality_local` — расстояние до выпуклой
  оболочки опорных пунктов плана (0 внутри).
- **Правдоподобие:** `|scale_ppm| > 200` или `|разворот| > 3°` — предупреждение о перепутанных осях или
  системах (пороги — параметры `localize`). Разворот до ~1–1.5° бывает законно — сближение меридианов при
  удалённом осевом меридиане МСК (4 из 83 регионов `data/geodetic`), поэтому порог 3°, а не 1°.

Предупреждения (`warnings`: `code`, `message`, `point`), кофакторы, оболочка, использованные σ и веса
и диагностика невязок сохраняются в JSON датума. Старые JSON читаются: недостающие поля — `None`,
пересчёты работают, точность и экстраполяция не определены.

Тесты: `pip install pytest && python -m pytest tests` (387 тестов, включая 83 региона из `data/geodetic`):
`tests/test_localization.py` — локализация и надёжность, `tests/test_datums.py` — пересчёты между системами
(контрольный пример ГОСТ, туда-обратно по всем 56 парам систем, сверка с PROJ по 7 параметрам, BLH ↔ XYZ,
Гаусс–Крюгер и своему поперечному Меркатору, задачи `helmert_7p` 83 регионов, датум ГНСС в локализации и CLI).

### Датум ГНСС-измерений

По умолчанию пары считаются заданными в WGS-84 — как раньше, результаты не меняются. Если ГНСС-координаты
в другой системе (ПЗ-90.11 от приёмника ГЛОНАСС, ГСК-2011, ITRF-2008, СК-42…), её указывают явно:

```
python -m mathdatum localize pairs_pz.csv -o datum.json --gnss-datum PZ-90.11
python -m mathdatum to-local datum.json wgs.csv -o local.csv --gnss-datum WGS-84   # точки в WGS-84 → ПЗ-90.11 → местные
python -m mathdatum to-wgs   datum.json local.csv -o wgs.csv --gnss-datum WGS-84   # результат в WGS-84
```

```python
d = localize(pairs, gnss_datum="PZ-90.11")        # рабочая проекция на эллипсоиде ПЗ-90
x, y, H = d.to_local(B, L, h, datum="WGS-84")     # точка в другой системе: сначала пересчёт по ГОСТ
```

Рабочая проекция строится на эллипсоиде этой системы, координаты в WGS-84 **не переводятся**. На участке
переход между системами по 7 параметрам — это почти точно сдвиг, разворот, масштаб и наклон высот, их и так
поглощают подобие и плоскость высот: разница двух вариантов на участке 5 км ≤ 1 мм для СК-42 (сдвиг ~160 м)
и ~1 мкм для WGS-84 / ГСК-2011 (`tests/test_datums.py`). Предварительный пересчёт лишь добавил бы погрешность
самих параметров (для СК-42 — до метров из-за локальных искажений сети). Система сохраняется в JSON датума
(`gnss_datum`); в старых JSON поля нет — при рабочей проекции на WGS-84 считается WGS-84, иначе пересчёт
из других систем недоступен. `--gnss-datum` у `to-local` / `to-wgs` — система точек файла, если она не
совпадает с системой датума (пересчёт по 7 параметрам, путь печатается в stderr).

## Пересчёты между системами (ГОСТ 32453-2017)

`mathdatum/datums.py` (и `Datums.kt` в Kotlin — те же формулы 1:1):

| Система | Код | Эллипсоид | Параметры |
|---|---|---|---|
| СК-42, СК-95 | `SK-42`, `SK-95` | Красовского | → ПЗ-90.11, прил. А.1, А.3 |
| ГСК-2011 | `GSK-2011` | ГСК-2011 | → ПЗ-90.11, прил. А.5 (эпоха 2011.0) |
| ПЗ-90, ПЗ-90.02, ПЗ-90.11 | `PZ-90`, `PZ-90.02`, `PZ-90.11` | ПЗ-90 | прил. В.1, Б.1 (эпоха 2010.0) |
| WGS-84 (G1150) | `WGS-84` | WGS-84 | → ПЗ-90.11, прил. Г.1 |
| ITRF-2008 | `ITRF-2008` | GRS80 | ПЗ-90.11 →, прил. Д.1 (эпоха 2010.0) |

```
python -m mathdatum systems                                                    # системы и параметры
python -m mathdatum transform sk42.csv -o wgs.csv --from СК-42 --to WGS-84     # B;L;h → B;L;h
python -m mathdatum transform gk.csv -o pz.csv --from SK-42 --to PZ-90.11 --in gk --out-format xyz
python -m mathdatum transform wgs.csv -o msk.csv --from WGS-84 --to SK-42 --out-format "tm:lon0=38.48333,x0=-5712900.566,y0=1250000"
python -m mathdatum transform mdvj.csv -o out.csv --from ITRF-2008 --to PZ-90.11 --in xyz --out-format xyz --epoch 2005 --target-epoch 2013.9
```

Форматы: `blh` — `name;B;L;h`; `xyz` — `name;X;Y;Z`; `gk` — `name;x;y;H`, Гаусс–Крюгер 6° (`gk:7` — зона 7);
`tm:lon0=…,lat0=…,k0=…,x0=…,y0=…` — свой поперечный Меркатор («МСК-подобные» системы; x0 — на север, y0 — на восток).
H плоских форматов — геодезическая высота; при подстановке нормальной план искажается на ~ζ·2·10⁻⁵ (0.5 мм при ζ = 25 м).

```python
from mathdatum import datums
datums.transform_blh(B, L, h, "СК-42", "WGS-84")             # через ПЗ-90.11 (путь — datums.find_path)
datums.transform_xyz(xyz, "ITRF-2008", "PZ-90.11", epoch=2005.0, velocity=v, target_epoch=2013.9)
datums.blh_to_xyz(B, L, h, "krass"); datums.xyz_to_blh(X, Y, Z, "SK-42")
x, y = datums.gk_forward(B, L, "krass")                       # y = n·10⁶ + 500 000 + E
B, L = datums.gk_inverse(x, y, "krass")                       # зона — по первым цифрам y
datums.TransverseMercator("krass", lon0=38.48333, x0=-5712900.566, y0=1250000).forward(B, L)
```

- **Формула ГОСТ** (поворот системы координат, малые углы; в PROJ `+convention=coordinate_frame`):
  `X2 = (1 + m)·R·X1 + ΔX`, `R = [[1, ωz, −ωy], [−ωz, 1, ωx], [ωy, −ωx, 1]]`. **Обратный переход** — точное
  обращение `X1 = (Rᵀ + ω·ωᵀ)·(X2 − ΔX) / ((1 + |ω|²)(1 + m))`: туда-обратно сходится до 1e-9 м. Упрощённое
  обращение сменой знаков параметров отличается на `(|ω| + |m|)·|ΔX|` — до 0.6 мм для СК-42; PROJ обращает через
  `Rᵀ` (расхождение ≤ 0.1 мм).
- **Цепочки** — кратчайший путь по графу параметров (все наборы ГОСТ связаны через ПЗ-90.11): СК-42 → ПЗ-90.11 →
  WGS-84 — прямой А.1 и обратный Г.1.
- **Эпоха** — только то, что определено ГОСТ: если заданы эпоха координат и скорость пункта (м/год), перед шагом
  с эпохой параметров (А.5, Б.1, Д.1) координаты линейно переносятся на неё, в конце — на целевую эпоху. Моделей
  скоростей нет; без скорости координаты считаются отнесёнными к эпохе параметров. Скорость пункта между
  системами не меняется (как в контрольном примере ГОСТ).
- **Почему свои формулы, а не PROJ:** Kotlin-порт обязан давать тот же результат без PROJ, поэтому эталоном служит
  одна реализация, повторённая 1:1, а PROJ — независимая проверка в тестах (7 параметров — до 1e-6 м,
  BLH ↔ XYZ — до 1e-6 м, Гаусс–Крюгер и поперечный Меркатор — до 1e-6 м).
- **Параметры** совпадают с `data/geodetic/gost_32453_parameters.json` (проверяется тестом). У СК-95 (прил. А.3)
  в файле был знак ωy = −0.00354″; исправлен на +0.00354″: наборы А.1, А.3, В.1, Г.1 — композиция параметров
  ГОСТ Р 51794-2008 (→ ПЗ-90.02) с прил. Б.1 (ωy = +0.00354″), и все остальные наборы с ней сходятся до последнего
  знака (`test_parameters_are_composition_with_b1`). Разница — ~0.2 м.
- **WGS-84:** в ГОСТ (и в файле данных) параметры есть только для реализации G1150 (прил. Г.1); для G1762 и более
  новых своих параметров нет, они не добавлены. Свой набор можно передать в `find_path(..., transformations=…)`
  или `transform_xyz(..., path=…)`.
- **Контрольный пример ГОСТ** (прил. Е, пункт Менделеево) воспроизводится полностью: шаг 1 (перенос эпохи
  2005 → 2010) — 1e-9 м, шаг 2 (ITRF-2008 → ПЗ-90.11, обратный Д.1) — 4.3e-5 м (в ГОСТ значения до 0.1 мм),
  шаг 3 (2010 → 2013.9 той же скоростью) — 2.3e-4 м (в ГОСТ — до 1 мм).

## Kotlin Multiplatform

`kmp/` — та же локализация и пересчёты между системами на Kotlin для Android, iOS, Web и Desktop,
с тестами против Python-эталона. Готовое веб-приложение: откройте `kmp/web-dist/index.html` в браузере.
Подробности — в `kmp/README.md`.

## Данные

- `data/nist_l2/` — эталонные МНК-подгонки NIST (прямая, плоскость, окружность, сфера, цилиндр, конус).
- `data/synthetic/` — машиностроение: МНК-плоскость, плоскостность по минимальной зоне, система датумов 3-2-1, совмещение с номинальной моделью.
- `data/geodetic/` — геодезия по 83 субъектам РФ: 7 параметров СК-42 → ПЗ-90.11 (ГОСТ 32453-2017), локализация ГНСС в местной системе.
  Генератор и проверка используют `mathdatum.datums` (проверка — дополнительно независимо через PROJ).

Описание форматов: `data/README.md`, `data/geodetic/README.md`.

```
pip install -r requirements.txt
python tools/verify_cases.py      # NIST + synthetic
python tools/verify_geodetic.py   # регионы РФ
```
