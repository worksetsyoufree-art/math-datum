# math-datum

Датумы и системы координат России: федеральные (СК-42, СК-95, ПЗ-90, ПЗ-90.11, ГСК-2011) и региональные/городские
местные системы координат (МСК) с параметрами перехода к WGS-84, проверкой и онлайн-конвертером.

**Сайт:** https://worksetsyoufree-art.github.io/math-datum/ — корневая `index.html` перенаправляет в `docs/` (само приложение).
Подходит любой источник Pages: ветка `/ (root)` или папка `/docs`. Локально: открыть `docs/index.html`.

## Что внутри

| Путь | Содержимое |
|---|---|
| `data/systems.json` | **подтверждённые** системы (258), по записи на зону/датум |
| `data/systems_unverified.json` | системы, не прошедшие подтверждение (80), с причинами |
| `data/datum_transforms.json` | 21 набор параметров перехода к WGS-84 без проекции (СК-42, СК-95, ПЗ-90.11, МГГТ …) со статусом сверки с EPSG |
| `data/federal_datums.json` | федеральные СК из реестра EPSG |
| `data/validation_systems.csv` | результат проверки каждой системы |
| `data/raw/` | сырые выгрузки с сайтов, экспорт Fieldworker (`fieldworker_datum_from_geod_wgs84.json`) |
| `data/msk_systems.*` | промежуточный набор: только два сайта, 490 строк (до слияния) |
| `docs/` | сайт: конвертер, таблица систем, датумы, проверки (proj4js 2.12.1 вендорен) |
| `scripts/`, `tests/` | сборка и тесты; `scripts/run_all.sh` пересобирает всё из `data/raw` |

Пересборка: `scripts/run_all.sh` (с `--scrape` — сначала заново скачать сайты). Нужны `pyproj`, `requests`, `beautifulsoup4`, `lxml`, Node 22.

## Источники

* [geoprof.nethouse.ru](https://geoprof.nethouse.ru/parametry-mestnyh-sistem-koordinat) — 79 страниц регионов, строки MapInfo `.prj`.
* [terraingis.ru](https://terraingis.ru/category/dannye-dlya-gis/msk) — 70 страниц, в т.ч. МСК-90 (Крым), МГГТ, подсистемы Красноярского края.
* Экспорт Fieldworker/GSI `datum_from_geod_wgs84.json` (340 записей, версия 2023-05-19).
* Реестр EPSG через pyproj 3.8 / PROJ 9.8 — федеральные датумы и эталонные операции (EPSG:5044, 5043, 15865).
* Не использованы: inner.su (SEO-страница с ошибочными параметрами), mapbasic.ru (недоступен).

## Правила слияния

* **Ложный север берётся из сайтов** (дробные значения вроде −5712900,566). В экспорте он усечён до целых метров; у зон, которых
  нет на сайтах, дробная часть восстановлена по соседней зоне региона (11 зон), если сосед усекается в то же целое. У 47 систем
  из экспорта дробная часть неизвестна (ошибка < 1 м) — это отмечено флагом.
* **Экспорт** задан в направлении WGS84 → местная СК, повороты в радианах и **без поворота вокруг оси Y**. Он переведён в форму ГОСТ
  (локальная → WGS-84, «coordinate frame»). Поворот ωy восстановлен только там, где остальные шесть параметров совпали с известным
  набором (сайты или EPSG: СК-42 → −0,35″); у 37 систем восстановлен, у 15 принят 0 с флагом.
* Сдвиги из экспорта и сайтов считаются одинаковыми при расхождении ≤ 0,05 м (в экспорте у МГГТ ΔZ = 589,659 против 589,650 на сайтах — взято значение сайта).
* В PROJ повороты MapInfo/ГОСТ инвертируются: проверено против EPSG:5044 (разница 0,000 см; без инверсии — 29,9 м).

## Что значит «подтверждена»

Система остаётся в `systems.json`, только если выполнено всё (`scripts/finalize.py`):

1. минимум два независимых источника совпадают по осевому меридиану, ложным координатам, широте начала и датуму;
2. пересчёт WGS-84 → МСК → WGS-84 замыкается (< 5 мм) на контрольных точках региона;
3. зона n ≥ 2 согласована с рядом зон региона (шаг 1,5° / 2° / 3° / 6° от зоны 1);
4. столица региона не дальше 260 км от осевого меридиана какой-либо зоны региона (у городских систем — свой город, ≤ 150 км).

Остальное не удалено, а лежит в `systems_unverified.json` с причинами; на сайте показывается по галочке.

## Результаты

* 338 систем в 81 регионе: **258 подтверждены**, 80 нет. Подтверждённые: 184 — все три источника, 64 — экспорт + geoprof, 9 — экспорт + terraingis, 1 — два сайта.
* Из 80 неподтверждённых 71 не прошли только из-за единственного источника (50 — из экспорта, 21 — с одного сайта). Остальные 9: зона-«призрак»
  МСК-29 с осевым 68,03° (не вписывается ни в один ряд зон), 4 астраханских «alt_IGD» (замыкание 12,8 мм из-за больших поворотов: линеаризованный Гельмерт PROJ),
  3 зоны Октябрьской ж/д и трасса М-11 без контрольной точки.
* Хакасия, МСК-19 (166): `lat0 = 0` подтверждён тремя источниками; вариант `0,37°` с terraingis остался неподтверждённым.
* Москва (МГГТ): `0 / 0` (geoprof и экспорт) подтверждены; вариант `16,098 / 14,512` с terraingis — одиночный.
* Датумы: СК-42 (EPSG:5044), СК-42 Trimble (EPSG:15865), СК-95-2008 (EPSG:5043) совпали с наборами EPSG; СК-95-2001 — с набором из определения EPSG:2754 (ГОСТ Р 51794-2001).
  ПЗ-90.11 и ГСК-2011 из экспорта (сантиметры) в EPSG соответствия не имеют — не подтверждены.
* proj4js (сайт) и PROJ (pyproj) совпадают на всех 336 контрольных точках, расхождение < 0,05 мм (`tests/proj4_parity.mjs`, выполняется в CI).

## Ограничения

* Проверки подтверждают осевой меридиан и ложный восток, **но не ложный север и не сам датум** — для этого нужны опорные пункты
  с известными координатами в каждой МСК (см. предложения ниже).
* Контрольные точки (`data/region_capitals.csv`, `data/extra_points.csv`) введены вручную с точностью ≈ 0,01° и независимо не сверялись.
* Нет данных: Тыва (17), Еврейская АО (79), ЯНАО (89), новые регионы (ДНР, ЛНР, Запорожская, Херсонская области) и часть
  городских/кадастровых подсистем. Полного каталога Росреестра в открытом виде найти не удалось.
* Экспорт Fieldworker содержит поворот ωy = 0 во всех 340 записях; применять его параметры «как есть» нельзя (≈ 10 м для СК-42).
* Сайт не заменяет официальный каталог Росреестра — для кадастровых работ сверяйте параметры с первоисточником.

## Предложения по дополнительным проверкам

1. Опорные пункты ГГС/ГНСС и кадастровые выписки: координаты одной точки в МСК и в WGS-84 — единственная проверка ложного севера и датума (допуск ~ 0,1 м).
2. Сравнение с независимой реализацией (QGIS/GDAL, ArcGIS, Credo) на тех же точках — ловит ошибки конвенции знаков и единиц.
3. Масштабные искажения на краю зоны (k ≈ 1 + (Δλ·cosφ)²/2): искажение у края зоны должно укладываться в допуск для МСК (допуск взять из нормативного документа).
4. Согласованность соседних зон: точка на стыке зон, пересчитанная через обе зоны, должна давать одно и то же в WGS-84.
5. Граница региона: все городские центры и границы кадастровых округов региона должны попадать хотя бы в одну зону с допустимым смещением (нужны границы субъектов).
6. Обратимость на сетке точек по всей зоне, а не только в столице (линеаризованный Гельмерт даёт мм–см при больших поворотах).
7. Кросс-проверка СК-63 ↔ МСК одного региона: известная связь по ФГИС/ЕГРН-таблицам перехода.
8. Контроль версий источников: хэши страниц и diff при повторном скрейпе, чтобы ловить правки параметров.
9. Проверка точности `towgs84` через цепочку СК-42 → ПЗ-90.11 → ГСК-2011 по ГОСТ 32453-2017 (нужны эталонные значения из стандарта).
