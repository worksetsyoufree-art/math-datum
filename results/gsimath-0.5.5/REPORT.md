# Проверка локализации gsimath-desktop 0.5.5 (model 1.2.54)

**Что проверялось:** `LocalizationRepository.getLocalization(...)`, вызванная так же, как в `LocalizationPairsImpl.calculate()`: датум WGS-84, одни и те же пары точек для плана и для высот.

**Как переносятся точки** (так же, как в приложении):
- путь приложения — `CommonMathRepository.calculateToActualCoordinate` с датумом, у которого `isFromLocalization = true`;
- прямой путь — `TransformCoordinateRepository.getTransformationTwoDatums`, с тем же датумом без этого флага.

**Данные:** `data/geodetic/regions/*.json`, задача `site_localization`, 83 субъекта. Участок около 5 км, 6 опорных и 4 контрольных пункта. Шум: ГНСС 1 см в плане и 2 см по высоте, каталог 5 мм.

**С чем сравнивалось:** с эталонным МНК (подобие по 4 параметрам и плоскость высот) и с каталожными координатами контрольных пунктов.

Запуск: `tools/kotlin_check/run.sh <gsimath.jar> <model.jar>`. Таблицы по регионам лежат в `site_<N>pts.csv`, сводки — в `summary_<N>pts.txt`.

## Как устроен алгоритм (по байткоду)

1. **Проекция.** Подбирается стереографическая проекция по 5 параметрам (B0, L0, FE, FN, k0) по всем парам точек. Решатель — `LeastSquaresImpl`, метод dogbox. Начальное приближение — первая точка.
2. **План (ГСКО).** По координатам в этой проекции подбирается подобие: центр вращения в центроиде, сдвиги, разворот, масштаб.
3. **Высоты (ВСКО).** Наклонная плоскость `H = h + a0 + a1(x − x0) + a2(y − y0)`. Подбираются все 5 чисел, включая x0 и y0.

## Результаты: 6 опорных пунктов, штатный сценарий

| Метрика, м | медиана | максимум |

| Невязки на опорных по высоте, библиотека / эталон | 0.003 / 0.003 | 0.007 / 0.007 |

- **План работает хорошо.** Ошибки на контрольных пунктах не хуже эталона, обычно на 1–5 мм лучше: у модели больше степеней свободы. Отказов нет, время 60–340 мс на регион.
- **Решатель ГСКО точен.** На уже спроецированных координатах (`GskoCheck`) `getGSKOLocalization` совпадает с эталонным МНК до 2·10⁻¹⁰ м во всех 83 регионах.

## Найденные проблемы

1. **Поправка по высоте не применяется в пути приложения** (ошибка высот на контрольных пунктах 6–30 м, то есть вся аномалия высоты).
   - `CommonMathRepositoryImpl.calculateToActualCoordinate` для датума с `isFromLocalization = true` делает `copy(paramVSKO = null)` (байткоде: маска `32255`, аргумент VSKO = `null`).
   - При заданной сетке геоида высота заменяется на `h − N`, и ВСКО тоже не участвует.
   - Через `getTransformationTwoDatums` с тем же датумом высоты верны (6 мм).
   - Нужно проверить, не пересчитывается ли высота в другом месте приложения. Если нет, это ошибка.

2. **Плоскость высот переопределена и плохо обусловлена.**
   - В `WrapperFunPlaneImpl` свободны все 5 параметров (a0, a1, a2, x0, y0). Но x0 и y0 линейно зависимы с a0, поэтому якобиан вырожден. Старт из нуля, координаты не центрированы.
   - **На больших координатах** (N ≈ 5·10⁶ м, прямой вызов `getPlaneLocalization`) решатель останавливается раньше оптимума в 32 регионах из 83. Невязки хуже МНК-оптимума на величину до 11.7 мм.
   - **В штатном сценарии** координаты стереопроекции меньше, и потери составляют ≤ 0.5 мм.
   - **При 3 опорных пунктах** плоскость определена точно, и невязки должны быть нулевыми. Библиотека оставляет до 8.5 мм, а прогноз на контрольных расходится с точным решением до 0.84 м.
   - **Исправление:** зафиксировать x0, y0 в центроиде (как это уже сделано для ГСКО) и решать линейный МНК по 3 параметрам напрямую.

3. **Нет проверки минимального числа точек.**
   - **1 пункт:**
     - план возвращает `Success`, ошибка на контрольных пунктах 22–83 м (разворот не определён);
     - по высоте в 51 регионе `Error`, в 32 — `Success` с невязкой до 19.8 м на единственной точке.
   - **2 пункта:**
     - по высоте плоскость не определена, а библиотека возвращает `Success` с произвольным наклоном;
     - ошибка на контрольных пунктах до 6.6 м (эталон со сдвигом по высоте даёт 0.18 м).
   - **Нужно:** при < 2 точках в плане и < 3 по высоте либо отказывать, либо переходить к упрощённой модели (только сдвиг).

4. **Неточная обработка ошибок** (по коду).
   - При исключении в подгонке проекции `getLocalization` возвращает `Error` и для плана, и для высот, даже если ошибка была только в одной из частей.
   - `LocalizationPairsImpl` в ветке «высоты Success, план Error» безусловно приводит проекцию к `ProjectionStereographic`.

## Что не проверено

- Задача `helmert_7p` (переход по 7 параметрам). `WrapperFun7ParamsImpl` есть в jar, но через `LocalizationRepository` недоступен и в приложении не используется.
- `getWgsMskLocalization` и `getMskMskLocalization`: в `LocalizationPairsImpl` они не вызываются.
- Большие участки (> 5 км), выбросы и вырожденная геометрия (точки на одной прямой). Наборы для этого можно добавить в генератор.
